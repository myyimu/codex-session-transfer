# Codex 任务连续性

一个本地优先的 Codex 桌面工具，用来让本地 Codex 任务在换机、备份、整理和侧边栏异常后保持可用。它支持选择性导出、导入、检查和重新登记项目任务会话。

它会扫描当前电脑里的 Codex 本地任务历史，按项目和任务名展示，支持勾选后打成 ZIP 压缩包；在另一台电脑上打开同一个应用，即可预览压缩包，把选中的项目任务会话导入到当前 Codex 数据目录。所有处理都发生在本机，不会上传会话内容。

[English README](./README.en.md) | [产品定位、界面与路线图](./docs/product-strategy.md)

## 产品定位

`Codex 任务连续性`解决的是“重要任务还在本地，但不方便继续使用”的问题：把任务安全地带到另一台电脑、保留一份可检查的本地归档，或在会话文件仍存在而侧边栏没有显示时重新登记它们。

它不是全量灾难恢复器：不会覆盖整个 `.codex` 目录，不承诺重建所有内部缓存、协作关系或跨对话长期记忆，也不会上传任何会话内容。

## About

Codex Session Transfer 适合这些场景：

- 换电脑时，把旧电脑上的 Codex 项目任务会话带到新电脑。
- 在多台电脑之间同步选中的 Codex 历史任务，而不是复制整个 `.codex` 目录。
- 备份重要任务会话，保留项目路径、任务标题、原始对话记录和浏览器会话配置。
- 本地已经存在会话文件，但 Codex 侧边栏看不到时，把本地历史重新恢复到 Codex 任务列表。
- 在导入前检查压缩包内容、重复任务和逐项目路径映射，以更可控的方式完成本地迁移。

## 功能说明

- **导出任务**：扫描本机 Codex 任务历史，按任务勾选后导出为标准 ZIP。
- **渐进扫描**：扫描到的任务会陆续显示；可取消扫描，超时后可继续扫描剩余任务。
- **按项目分组**：搜索框右侧提供项目下拉框，支持按 Codex 项目分组筛选任务。
- **任务搜索**：支持按任务名、项目路径和会话内容关键词搜索。
- **项目状态标记**：项目路径不存在或未在 Codex 侧栏显示时，会在列表和项目下拉框中标记，并放到靠后位置。
- **导入任务**：在新电脑预览 ZIP 内容后导入当前 Codex 数据目录。
- **重复任务处理**：默认跳过本机已存在的任务；也可以重新登记本地历史。归档严格包含本地记录时可显式补全，本地更完整时保留本地，历史分叉时停止自动处理。
- **逐项目路径映射**：按压缩包中的项目逐项确认本机目录；路径完全一致或只有一个同名候选时会自动预选，多候选或无候选时由用户选择。
- **写入兼容性预检**：导入或重新登记前检查当前 Codex 数据库与侧边栏状态结构；遇到未知的新结构时停止写入并保留原数据。
- **接收端配置适配**：导入的历史会保留原始对话和历史模型信息，但可继续使用的会话上下文会改用这台电脑当前的 Codex provider、模型和推理配置。
- **路径候选发现**：从现有 Codex 项目和用户目录、`~/work`、`~/Projects`、`~/Documents`、`~/Desktop` 等常用位置查找同名项目；不会创建占位目录。
- **运行中保护**：导入前会检测 Codex/ChatGPT 桌面端主进程。如果 Codex 正在运行，会提示先退出，避免 Codex 用内存状态覆盖恢复结果。
- **重新显示任务**：当本地会话仍存在、但未在 Codex 中显示时，按项目分组选择需要处理的任务后，可安全重新登记。
- **本地安全备份**：导入或重新登记前自动保留 Codex 本地状态备份，降低误操作风险。

## 恢复边界

- 可处理：会话文件迁移、任务标题和项目元数据、侧边栏重新显示、逐项目路径映射与绑定，以及写入前关键本地状态备份。
- 不承诺：覆盖全部 Codex 数据、强制修复所有排序和缓存、恢复未导出的内部协作关系，或精确合并跨任务长期记忆。
- 设计原则：任何会写入 Codex 本地状态的动作，都应先退出 Codex，先预览影响，再保留本地安全备份。

详细的价值判断、两视图交互设计和分期计划见 [产品策略](./docs/product-strategy.md)。

## 安全备份

导入或重新显示任务前，应用会自动保留本机 Codex 状态的安全备份。备份默认不会自动删除；需要时可在一次修复完成后进入“管理本地备份”查看并手动清理。

- 备份只保留在当前电脑，不会上传。
- 应用不会自动清理缓存、调整排序或覆盖整个 `.codex` 目录。
- 建议在真实迁移或重新显示任务后，先重新打开 Codex，确认任务可见且可继续对话，再开始大量新任务。

## 页面教程

### 1. 导出任务

打开应用后默认进入“导出任务”。列表中会显示任务标题、更新时间、项目路径和对话轮数。勾选任务后，可以点击右上角或底部的“导出压缩包”。

### 2. 按项目筛选

点击搜索框右侧的项目下拉框，可以按项目筛选任务。已删除、缺失或未在 Codex 侧栏显示的项目会带有状态标记，方便判断是否需要迁移或恢复。

![项目筛选](./docs/screenshots/readme/project-dropdown.png)

### 3. 重新显示未显示的任务

当导出页提示“任务暂未在 Codex 中显示”时，点击“处理任务”。应用会按项目分组展示可处理的任务；默认不选中任何任务。选择后执行“安全备份并修复”，再重新打开 Codex 查看结果。

### 4. 导入压缩包

切换到“导入任务”，拖入或选择由本应用导出的 `.zip` 压缩包。应用会先预览压缩包，不会立刻写入 Codex 数据。

![导入压缩包](./docs/screenshots/readme/import-empty.png)

### 5. 处理重复任务和项目映射

选择压缩包后，可以看到每个任务的导入状态：

- `可导入`：本机没有这个任务，会作为新任务导入。
- `已存在，将跳过`：本机已有同 ID 任务，默认不覆盖。
- `从本地历史恢复`：本机已有会话文件，但需要重新注册到 Codex 任务列表时使用。
- `补全本地`：仅在归档完整包含本地历史并且拥有额外记录时可选；本地更完整时保留本地，双方历史分叉时不会自动合并。

应用会按本次实际处理的任务展示项目路径映射。路径完全一致或只有一个同名本机目录时会自动预选；有多个候选时需要手动选择，没有候选时可以浏览本机目录。只包含“跳过”任务的项目不会阻塞导入；没有项目路径的任务会保持未绑定。

## 模型与 API 路由适配

导入归档时，应用把会话内容视为可迁移的历史，把 provider、模型和推理配置视为接收电脑的本地运行状态。无论历史任务来自官方配置还是自定义 API 路由，可继续使用的会话上下文都会适配到这台电脑当前的 Codex 配置。

- 导出的 ZIP 会保留原始会话内容和任务历史。
- 列表中显示的历史 provider 和模型信息仅用于识别来源，不代表导入后仍会使用旧配置。
- 导入或恢复到新电脑时，可继续使用的会话上下文会改写为接收电脑当前的 provider、模型和推理配置。
- 应用不会迁移第三方 API key、路由配置、代理配置或外部模型服务账号。

如果你希望新电脑继续使用与旧电脑相同的第三方路由，需要先在新电脑单独配置对应的 provider、API key 和网络设置，再执行导入。

## 使用步骤

### 从旧电脑导出

1. 打开 `Codex 会话迁移`。
2. 进入“导出任务”。
3. 使用搜索框或项目下拉框找到要带走的任务。
4. 勾选任务，或点击“全选当前结果”。
5. 点击“导出压缩包”，保存生成的 `codex-tasks-YYYY-MM-DD.zip`。

### 在新电脑导入

1. 把 ZIP 压缩包复制到新电脑。
2. 完全退出 Codex/ChatGPT 桌面端：macOS 使用 `Cmd + Q`；Windows 请从托盘或应用菜单退出，并确认主进程已经结束。
3. 打开 `Codex 会话迁移`，进入“导入任务”。
4. 选择 ZIP 压缩包并检查任务预览。
5. 检查重复任务处理方式，并逐项目确认本机路径映射。
6. 点击“确认映射并导入”。
7. 重新打开 Codex/ChatGPT 桌面端，在侧边栏查看恢复后的项目和任务。

## 重复与恢复规则

导入默认不会覆盖已有任务。应用使用 Codex 任务 ID 判断重复：

- 本机不存在的任务会写入 Codex 会话目录。
- 本机已存在的任务默认跳过，不改原始会话文件。
- 选择“从本地历史恢复”时，应用会把本机已有会话重新注册到 Codex 任务列表，并取消归档/隐藏状态。
- 重复任务会按有序会话记录比较，并忽略接收电脑的路径、provider 和模型字段差异。归档是本地历史的严格超集时，可以显式选择“补全本地”。
- 本地是归档的严格超集时保留本地；内容一致时不改会话文件；共同历史之后双方分别新增记录时标记为分叉，不按时间戳猜测合并或覆盖 JSONL。
- 项目路径映射只接受已经存在的本机目录；历史项目缺失且未选择目录时不会创建占位文件夹。
- 导入归档中的会话会适配到接收电脑当前的 Codex provider、模型和推理配置。
- 如果 Codex/ChatGPT 桌面端正在运行，应用会阻止导入，避免侧边栏状态被运行中的客户端覆盖。

## 下载

在 GitHub Releases 中下载最新版本：

**最新下载地址：** [github.com/myyimu/codex-session-transfer/releases/latest](https://github.com/myyimu/codex-session-transfer/releases/latest)

macOS 解压后直接打开 `.app`。如果系统提示无法打开，可在 Finder 中右键应用并选择“打开”。

### macOS 授权打开

如果 macOS 提示“无法打开，因为无法验证开发者”，可以先尝试：

1. 在 Finder 中右键 `Codex 会话迁移.app`。
2. 选择“打开”。
3. 在系统确认弹窗中再次点击“打开”。

如果仍然无法打开，并且你确认应用来自本仓库 Releases，可使用命令移除隔离标记：

```bash
xattr -dr com.apple.quarantine "/Applications/Codex 会话迁移.app"
open "/Applications/Codex 会话迁移.app"
```

如果应用还在下载目录，把路径换成实际位置，例如：

```bash
xattr -dr com.apple.quarantine "$HOME/Downloads/Codex 会话迁移.app"
open "$HOME/Downloads/Codex 会话迁移.app"
```

## 压缩包格式

导出的 ZIP 根目录包含 `manifest.json`，每个任务位于 `tasks/<task-id>/`，保留原始 `session.jsonl` 与可选的 `browser.toml`。

归档可能包含完整对话、项目路径、工具执行上下文和浏览器会话配置。请把 ZIP 当作敏感本地数据保管，不要上传到公开网盘、Issue 或聊天群。

当前格式版本为：

```text
codex-session-transfer/v1
```

## 隐私说明

应用只读取本机 Codex 数据目录，并在本机生成或导入 ZIP 文件。它不会上传会话内容，也不需要服务器。导出的归档由用户自行保管；删除应用不会自动删除已经保存到其他位置的 ZIP。
